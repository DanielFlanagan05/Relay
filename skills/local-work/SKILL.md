---
name: local-work
description: Keep repository implementation and verification focused when working through a local coding harness.
---

Read the assignment and latest relevant handoff first. Search paths and symbols before reading large files; read only the matching sections and nearby callers. Batch independent small reads. Avoid repeated full plans, transcripts, directory listings, or tests whose result is already known and unaffected.

Complete one bounded implementation slice, run focused checks, and report changed files, observed results, and remaining work. Shared-checkout builds and broad suites need an agreed integration point; concurrent writers can create transient failures. Do not treat another agent's report as independently verified evidence.

When resuming, inspect saved history, current files, and your own task status before editing. Claim a restart, compaction, lost file, or completed test only with evidence. A quiet stream does not establish a stall. If context is getting large, write a short evidence-based handoff rather than rereading everything.

Do not load models, benchmark inference, alter runtime memory settings, or spawn agents merely to validate code. Honor the user's test constraints. When runtime testing is outside scope, name the concrete future check.
